# 製作專屬桌寵流程頁 - Team Run

## 分類與完成定義

- Profile: web + docs
- Risk: low
- 目標: 在官方網站新增「製作專屬桌寵」頁籤與獨立流程頁，讓玩家能依照主程式 AI 素材助手的實際順序完成素材製作。
- 範圍: 導覽、首頁教學入口、繁中/簡中/英文內容、四個步驟截圖、SEO、網站驗證、桌面與手機檢視。
- 不在範圍: 網頁端上傳素材、呼叫 AI 服務、修改桌面程式、GitHub Pages 發布。

## 角色會議

| 角色 | 決策 |
| --- | --- |
| PM | 將操作拆成「準備參考素材」、「選擇 Prompt 與輸出方式」、「檢查素材與裁切」、「匯入指定姿勢」四步，避免玩家在多個頁籤間尋找下一步。 |
| UI/UX | 使用單一路徑的由上而下流程；每一步都包含清楚標題、說明、完成條件與圖片輔助。 |
| Lead Developer | 建立獨立靜態頁，沿用共用導覽、語言切換與既有視覺 token；實際主程式畫面以本機截圖作為步驟輔助。 |
| QA | 驗證三種網站語言、導覽、鍵盤焦點、手機單欄版面、圖片比例與 console。 |
| Technical Writer | 只描述目前已存在的 AI 素材助手、背景檢查、宮格裁切與手動姿勢匯入功能；不暗示網站會直接生成素材或自動覆寫設定。 |
| CEO | 將可自訂角色的創作門檻降至清楚的四步，作為產品與工作坊內容的入口。 |

## 方案比較與採用

1. 獨立流程頁: 導覽清楚、可分享、可被搜尋，且能承載每一步圖片。採用。
2. 直接插入工作坊 JSON 頁: 技術文件與玩家素材流程混在一起，閱讀負擔較高。不採用。
3. 首頁彈窗: 不利於長流程、行動裝置與搜尋。 不採用。

## WBS

| 工作 | Owner | 依賴 | 驗證 |
| --- | --- | --- | --- |
| 建立使用者故事與功能需求 | PM | 無 | 文件完整且可對照 |
| 定義流程頁資訊架構與響應式畫面 | UI/UX | PM 文件 | UI/UX 規格 |
| 新增頁面、導覽、圖片與樣式 | Lead Developer | UI/UX 規格 | 靜態驗證與瀏覽器檢視 |
| 更新 sitemap 與驗證腳本 | Lead Developer | 新路由 | `validate_site.py` 通過 |
| 跨語系、桌機、手機與 console QA | QA | 實作完成 | Playwright 證據 |

## Definition of Done

- 新頁面提供四個由上而下的製作步驟，且每步都有圖片與明確下一步說明。
- 導覽在所有公開頁面一致顯示新頁籤並在新頁正確標示目前頁面。
- 繁中、簡中、英文可切換且不混出重複內容。
- Sitemap 和靜態驗證涵蓋新頁。
- 桌機與手機瀏覽器驗證通過；未進行外部發布。
