# 實況模式官方網站介紹 - UI/UX 規格

## 資訊架構

1. 導覽：在「產品介紹」後加入「實況模式」，將 Twitch 功能從一般產品文案中抽出成獨立入口。
2. 首頁：Twitch 區保留為高辨識度摘要，使用一個主要 CTA 前往完整設定教學，一個次要 CTA 前往創作者 JSON 指南。
3. 新頁英雄區：以桌寵、Bits 籌碼和觀眾氣泡建立「觀眾支持會立即化為角色反應」的第一印象。
4. 設定流程：四個等寬步驟卡由左至右（行動版由上至下）說明；每張卡同時呈現行動、結果與關鍵限制。
5. 深入區：依序放置 Bits 規則、觀眾氣泡、本機測試與回復動作、OBS 擷取、資料與工作坊說明，避免把不同操作混在一個大段落。
6. 行程提醒視覺：使用行事曆卡、四個任務標籤、提醒氣泡與像素桌寵；標籤分散但不遮蔽角色或重要文字。

## 元件與動態

- Bits、日期與行程標籤採短週期、低位移的浮動動畫；不依靠動畫才可理解內容。
- 已有的六幀姿勢素材用於桌寵預覽，不生成新的虛構 UI 截圖。
- 對有 `prefers-reduced-motion` 的使用者停用視覺動態，保留靜態場景與可讀對比。
- 按鈕採既有珊瑚、奶油黃、綠色的明確層級；文字與背景的對比要符合現有可讀性標準。

## 響應式與無障礙

- 桌機以 2 欄或 4 欄資訊布局呈現；1060px 以下改為單欄，避免表格與步驟壓縮。
- 手機版每個主要 CTA 最小高度 44px，流程卡與 OBS 視覺不使用固定高度裁切文字。
- 純裝飾圖使用 `aria-hidden`；說明性的場景提供角色與提醒意義相符的替代文字。
- 導覽列擴充後仍沿用行動版選單，不讓語言選單或品牌名稱被壓縮。
