# 官方網站：響應式節奏與錨點修正

## 團隊執行紀錄

- 日期：2026-08-07
- Profile：web
- 風險：low
- 深度：standard
- 範圍：`index.html`、`privacy.html`、`terms.html`、`creator-json.html` 與共用 `assets/css/site.css`
- 不在範圍：網站內容架構、資料處理行為、第三方整合與 JavaScript 功能

## User Stories

1. 作為手機訪客，我希望首頁下方區塊的行動按鈕置中，讓內容在窄螢幕上保持穩定的視覺重心。
2. 作為網站訪客，我希望回到頁首按鈕不遮住頁腳內容，仍能隨時快速回到頁首。
3. 作為閱讀隱私權政策或使用條款的訪客，我點選摘要卡片後希望先看見對應段落標題，而不是跳到標題下方的內文。
4. 作為創作者，我希望創作者頁的行動按鈕與內容寬度一致，並在展開主題時能清楚看見控制符號與對應內容。

## 條件式功能需求

- 當螢幕寬度小於等於 600px 時，首頁非 Banner 區塊的 `.button-row` 應置中排列；多個按鈕可換行，但不得貼齊左右邊緣。
- 當回到頁首按鈕顯示時，桌機與手機的固定底部間距皆應高於頁腳的最低可讀區，且不遮住頁尾連結與版權資訊。
- 當點選法律頁的摘要卡片時，URL 對應的錨點應設在各語言內容區的 `h2`，並使用共用 `scroll-margin-top` 留出固定頁首空間。
- 隱私權政策的摘要及段落標題應顯示「支援 Google 行事曆同步」；使用條款的摘要及段落標題應顯示「素材自己決定」。英文與簡中使用語意對等文案。
- 創作者頁的三種分享包卡片與其下方「查看姿勢 JSON」按鈕應共用相同最大寬度；桌機按鈕應與三張卡片群組同寬，手機則與單張卡片同寬。
- 創作者能力卡片應為單欄清單。展開時內容只向下延伸，`+`／`-` 控制符號固定在列的最右側；桌機卡片寬度應與上方卡片群組一致。

## UI/UX 決策

- 使用中央 `max-width: 940px` 的內容軸線，讓三張分享包、其統合行動按鈕與八個能力主題形成一致的閱讀區。
- 卡片插圖留在標題列右側，但和 `+`／`-` 保持獨立位置；展開後的動作按鈕置於內容區正常流內，避免像排版跑位。
- 法律摘要卡片保持可整張點擊，錨點只負責定位到閱讀者可辨識的標題。
