# 官方網站跨瀏覽器與 SEO 優化

## 團隊摘要

- Profile：靜態多語系產品網站
- Risk：中等。變更會影響公開 GitHub Pages、搜尋結果與手機導覽。
- 範圍：`creator-json.html`、`support.html`、共用 CSS/JavaScript，以及 SEO 發布檔案。
- 非範圍：不變更產品功能、OAuth 設定、帳號資料或外部服務。

## 使用者故事

1. 身為創作者，我能在展開主題卡片後同時閱讀內容、看到縮小動畫並前往對應 JSON 範例，不必在分離的區塊尋找下一步。
2. 身為手機使用者，我能滑過所有八個主題而不會看到動畫延遲留下的大段空白；回到頂端按鈕也不會遮住頁腳內容。
3. 身為需要協助的玩家，我能在和支援提示同寬的常見問題清單中快速找到答案。
4. 身為從搜尋或分享連結進站的玩家，我能看到正確頁面標題、描述與分享縮圖，並讓搜尋引擎取得完整站點清單。

## 條件式需求

- 當創作者卡片展開時，內容、條列與 JSON 範例按鈕必須位於左側內容欄，動畫必須在右側欄並縮小；收合與展開按鈕的右側留白必須相同。
- 當畫面寬度小於等於 600px 時，創作者主題卡不得套用逐張進場隱藏動畫；內容在滑入可視範圍時必須立即可讀。
- 當頁腳進入可視區時，Top 按鈕必須上移；沒有足夠可視高度時必須隱藏，不得覆蓋頁腳連結。
- 常見問題清單寬度必須與同頁支援提示框一致。
- 所有公開頁面必須具備唯一標題、描述、Canonical、Open Graph、Twitter card 與 `index, follow` robots 設定；站點必須提供 robots.txt 與 sitemap.xml。

## 驗證矩陣

| 項目 | 驗證 |
| --- | --- |
| Chrome | 實際 Chrome 執行檔：桌面、手機寬度、Creator 展開、頁腳、Console |
| Edge | 實際 Edge 執行檔：同上 |
| Safari 相容性 | Playwright WebKit 引擎：同上。Windows 無法安裝原生 Safari，因此將限制如實記錄。 |
| SEO | 靜態驗證、sitemap/robots、HTML metadata、既有 `validate_site.py` |

## 完成定義

- 三個瀏覽器引擎的檢查路徑完成，沒有 Console error。
- 手機與桌面截圖確認卡片、FAQ 和 Top 按鈕位置。
- 驗證腳本與 Git 狀態乾淨後才推送 `main`。
